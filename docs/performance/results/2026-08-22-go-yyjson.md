## Comparison boundary

Four exact-size fixtures—500 KiB, 1 MiB, 4 MiB, and 16 MiB—use the same deterministic generation
algorithm as `benchmarks/benchmarks_test.go`. Each size has three DOM operations:

- Read: yjson `YJson.parse(Array<Byte>)` versus Go yyjson `yyjson.Read`;
- Write: yjson `YJson.stringify` versus Go yyjson retained `Doc.Write`, both using pre-parsed DOMs;
- RoundTrip: parse followed by compact write.

This is a mutable Cangjie `JsonNode` versus Go yyjson DOM latency comparison. It does not compare
generated typed codecs, and it does not make allocation or RSS claims.

## Results

`yjson / yyjson` is the latency ratio, so a value above `1.00x` means Go yyjson was faster. Medians
and CVs summarize the 11 per-process observations. All 12 rows had the same direction in 11/11
pairs.

## Variance follow-up

The initial 4 MiB Read series was noisy. A focused longer rerun with 24 iterations and four warmups
produced the accepted 92.405 ms / 23.973 ms row with CV 4.78% / 1.43%.

The 16 MiB Read series remained noisy after a focused rerun with 12 iterations and three warmups.
yjson ranged from 407.500 ms to 579.496 ms around a 522.471 ms median; Go yyjson's median was
103.646 ms. The observed ratio range was 3.93x–5.59x, so only the faster direction is retained.

## Limitations and artifacts

The result compares different languages, runtimes, garbage collectors, and DOM representations.
CPU affinity was fixed, but the host was not fully isolated. The Go module requires Go 1.25 and was
built with `-buildvcs=false -trimpath -ldflags=-s` using the Go version listed above.

The 264 main raw rows, focused reruns, metadata, binaries, and fixtures are retained on the Server at
`<home>/yjson-vs-go-yyjson-formal-20260822/evidence` and locally under the ignored directory
`target/perf-yjson-vs-go-yyjson-formal-20260822`. The Go adapter is not checked into this repository,
so the historical result is not independently reproducible or externally auditable from a checkout
alone.
