# 性能设计结论

本页说明 `0.1.x` 已采用的性能设计及其取舍。具体测量数据见[带日期结果](performance/README.md)。

## 已采用

- 生成的编解码器直接进入统一的读写器，不先构建 AST；
- 字符串、字节数组和流共用解析逻辑，不维护第二套配置或错误语义；
- `JsonValueView` 让序列化器、Pointer、Path 和 Schema 读取不同存储结构，无需先复制成 JSON 树；
- `JsonPath.matches()` 返回惰性游标，`first()` 在首个匹配后停止；
- Schema 引用关系和正则表达式在构造阶段冻结，校验不再执行外部 I/O 或重复编译；
- 普通 `YJson` 在引擎冻结后只读取原子冻结标志，不再进入进程级互斥锁；
- Native 和 yyjson 在序列化根节点或复制文档时，用一次读锁导出内部 tape 数据；
  保留的子视图每次访问仍需与 `close()` 同步；
- Large Map 编码使用单次遍历和直接输出，避免排序、树复制和二次扫描；
- 直接读取器只在重复键策略要求拒绝时分配字段名集合；
- Pure 是默认引擎；原生加速只在首次 `YJson` 调用前显式初始化；
- Native 和 yyjson 后端只通过专用入口暴露，普通 API 不承担策略分派。

## 未采用

- 持有调用方缓冲区的可复用解码会话：会扩大生命周期和并发约束；
- 按输入动态切换解析器或后端：会增加热路径分支和不可预测状态；
- 将借用视图作为生成编解码器的默认路径：会把输入的生命周期限制带入普通类型 API；
- 为单一测试数据形状增加产品专用入口；
- 运行期安装、卸载或自动回退原生实现；
- 向普通 `YJson` API 注入任意后端策略；
- 在 JSONPath `first()` 前先收集全部匹配，或在每次校验前重新解析 Schema；

调整默认实现前，必须先验证行为一致，再用固定 CPU 的交替、反转 A/B 测试比较性能。
测试还需检查校验和、记录 RSS，并在不同配置下重复。
