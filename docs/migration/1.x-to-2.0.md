# 从 1.x 迁移到 2.0

yjson 2.0 是 breaking redesign，不提供 deprecated alias 或兼容 shim。升级时应一次更新
`yjson`、`yjson_macros` 和生成代码。

## 默认调用不再选择 backend

普通应用保留三条主入口：

```cangjie
let text = YJson.toJson(value)
let value = YJson.fromJson<MyType>(text)
let document = YJson.parseDocument(text)
```

删除 `parseDocument`、`toStream`、`fromStream` 以及显式 codec stream 入口上的 `backend:`
参数。默认 stream reader/writer 保持增量语义。

默认 `JsonDocument` 是 GC 管理的只读 Compact representation；删除
`backendName()`、`close()` 与 `isClosed()`。使用 `root()`、`materialize()` 或 `toString()`。

## Native 加速只在启动时选择一次

依赖 `yjson_native_accel` 后，在任何 `YJson` 调用之前执行：

```cangjie
YJsonNativeAccel.initialize()
```

随后继续使用普通 `YJson` API。重复相同初始化是幂等的；晚初始化、provider 竞争以及
ABI/protocol 不匹配抛出 `JsonAccelerationException`。2.0 不支持 uninstall 或运行期切换，
初始化成功后的 provider 故障也不会静默回退到 Pure。

需要 yyjson DOM、Custom Native DOM 或 whole-document stream 的应用改为依赖
`yjson_backends`，并显式调用 `YJsonAdvanced.*WithBackend`。这类
`BackendJsonDocument` 仍是 resource，仍需确定性关闭。

## 配置 limits 独立组合

资源限制从行为配置中拆出：

```cangjie
let readConfig = JsonReadConfig(limits: JsonReadLimits(
    maxDepth: 64,
    maxBytes: 1024 * 1024,
    maxStringBytes: 256 * 1024
))

let writeConfig = JsonWriteConfig("", "", false, false,
    limits: JsonWriteLimits(maxDepth: 64, maxBytes: 1024 * 1024))
```

## 高层算法移入可选包

`JsonPointer`、`JsonPatch`、`JsonMergePatch`、`JsonPath` 与 `JsonSchema` 移入
`yjson_algorithms`。Schema resolver 更名为 `UriResolver`；未注入 resolver 时不会解析
外部 URI，更不会默认访问网络。

算法现在默认使用有限预算。预算耗尽统一抛出
`JsonWorkLimitException(code: "work_limit_exceeded")`。可信离线任务可以显式传入对应
`JsonPathLimits.unlimited`、`JsonPatchLimits.unlimited` 或 `JsonSchemaLimits.unlimited`。

## Generated codec protocol

宏输出嵌入 generated support protocol v1。支持层 protocol 未变化时，生成代码可以跨 patch
版本使用；不匹配时会以明确的 `generated_protocol_mismatch` 失败。生成源码不再引用具体
reader/writer 实现类。
